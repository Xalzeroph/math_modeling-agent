**A题库位分配优化 (2026-05-21)**: 读了5篇本地+5篇外部优化/调度论文。AS/RS货位分配+堆垛机调度类问题标准范式为"贪心启发式baseline→GA/SA优化→多策略仿真对比"。大规模(65000箱)组合优化不能求精确解，必须用启发式+模拟。双深位货架的"倒腾"操作用预留缓冲区解决。自创"货位热度"H_i=f_i√q_i指标指导分配。RGV调度论文的方法可迁移：0-1规划建模+多阶段决策+多原则对比。关键反模式：试图精确求解NP-hard问题、忽略双深位约束→论文不可信、所有候选方案同属一个算法家族。
- 方法选择: 仓库类100%用模型递进(贪心→GA→SA)；调度类标准范式为"0-1规划建模→启发式求解→多策略对比"；大规模问题必须分解(按约束优先级逐层分配)
- 章节结构: 模型40-50%/求解20-30%/评价10-15%；调度问题必配甘特图；多策略对比用表格而非纯文字
- 常见错误: 忽略层高约束导致箱子放不进、忽略双深位倒腾时间→出库时间估计偏低、MILP用于万级变量不收敛、只用一个调度策略不给对比

**A题空调调度灵敏度 (2026-05-19)**: 4参数±20%扰动分析。敏感性排序: R(热阻,|Delta|max=41.18%) > C(热容,35.29%) ≈ Tout(温度,29.41%) > EER(能效比,0%)。R最敏感的物理原因: R直接决定热传导速率DeltaT/R。EER最不敏感原因: 启停控制下EER不影响稳态占空比。联合扰动R-20%+Tout+1C产生非线性交互效应(不适度29.53远非线性叠加)。
- 方法选择: 优化类问题100%用模型递进(简单→复杂→情景)；电力调度类标准范式为"线性化近似→约束优化→多目标权衡"；含微分方程约束时必用数值离散化(隐式格式优先)
- 章节结构: 模型40-50%/求解20-30%/评价10-15%；多目标优化建议用字典序(Pareto)而非加权和；Strengths & Weaknesses必写(3-5条优势+3-5条局限)
- 常见错误: 加权和多目标不论证权重合理性、微分方程显式离散化导致数值不稳定、大规模优化不设计分解策略、蒙特卡洛采样次数不足

### 一、优化模型

**核心建模规律：**
- **自创指标是O奖标配** — 不套用标准优化目标（如最小成本）。案例：2016E自创EWR=(供水量-总用水)/总人口，与WSI做相关性验证
- **模型递进** — 简单模型→复杂模型→情景/干预模型。案例：2016F三个模型递进 Weighted→Goal Programming→Dynamic
- **多算法对比必做** — 试用3-4种算法对比优劣。案例：2015D对比GA/Nelder-Mead/Powell/PSO，PSO最优
- **模型组合**：LP+元启发式(GA/PSO/SA)+灵敏度分析

**O奖常用策略：** B题用整数规划/网络流+GA/PSO对比+灵敏度。A题用ODE+参数估计+灵敏度。

**常见错误：** 只用标准目标不自创指标、算法选型不给理由、缺少对比、灵敏度只做单参数OAT
**怎么做：**
- 想自创指标？先找出问题的核心矛盾->设计量化公式->用已有标准方法验证合理性
- 想做多算法对比？选 3-4 种不同家族的算法（如 LP + GA + SA），用收敛曲线对比
- 想做模型递进？先建简单模型（线性/回归）->再建复杂模型（非线性/混合）->最后做情景分析

**种子记录：** seed-2006-MCM-A(optimization,95分), seed-2004-MCM-B(optimization,92分)

|---------|------|------|
| 策略 | 自创指标+2-3种元启发式对比 | LP/NLP+1种智能算法+灵敏度 |

### 二、评价模型

**核心建模规律：**
- **自创评价指标体系** — 理解核心维度→量化指标→熵权/AHP定权→TOPSIS/灰色关联排序

**O奖常用策略：** F题用指标体系+多目标规划+政策建议。E题用自创指标+仿真+干预政策。

**怎么做：**

- 想做组合赋权？先用熵权法得客观权重->AHP得主观权重->组合权重取0.5:0.5

### 反模式 C: 模型选择

**C1 🔴 教科书原样模型** — 直接用标准模型名，无任何针对问题定制。修复：命名变体，如"动态加权AHP-熵权模型"。
**C2 🔴 模型与问题类型不匹配** — 预测题用评价模型，分类题用回归。修复：读 algorithms/index.json 确认映射匹配。
**C3 🟡 备选方案同属一个家族** — 3个候选模型全是线性回归的不同变体。修复：至少2个结构上不同家族的方法。
**C4 🟡 选择理由薄弱** — 只说"XGBoost效果好"无分析。修复：4维理由：拟合度+数据量+可解释性+计算成本。
**C5 🔴 无可行性测试** — 选完模型直接上全量数据。修复：50行 toy demo 验证后再上全量。
**C6 🟡 违反题目递进逻辑** — 在前面的子问题中使用了后面子问题才给的参数。例如P3(入库-出库协同)阶段题目没给满载速度，模型应全部使用空载速度；P4才给满载/空载区分+加速度参数。提前使用会导致模型逻辑不正确，且被评审视为对题目设计理解不足。修复：倒着读题——先看P4给了什么参数，再决定P3能不能用。

### 八、通用最佳实践

**假设要单独列节** — 每条编号+声明+合理性解释，通常5-10条。2015D按统计/环境/政策三类分组。

**灵敏度分析不可省略** — 至少3个关键参数±20%扰动。建议多参数联合扰动。美赛100%有，国赛更强调检验。

**Strengths and Weaknesses 是必写** — 优势3-5条（创新、改進、价值），局限3-5条（假设局限、参数敏感、未考虑因素）。美赛标配，国赛叫"模型评价与改进推广"。

**数据来源要权威** — 优先政府公开数据（世行/FAO/UNHCR）和SCI期刊论文，每个数据标注来源。

### 三原则速查
```
1. 能用初等方法解决的就不用高等方法
2. 能用简单方法解决的就不用复杂方法
3. 能用被更多人看懂理解的方法就不用少数人看懂理解的方法
```

## ━━━ 第 2 章  核心职责与执行流程━━━

### 2.1  核心职责

1. **题目分析**: 深入理解题目背景、问题和要求
2. **模型选择**: 选择合适的数学模型和算法（参考 `algorithms/` 算法资源库）
3. **算法设计**: 设计详细的求解流程和算法步骤
4. **术语规范**: 建立术语表，确保全文术语一致性
5. **文档产出**: 产出完整的分析文档和术语表格

### 2.2  模型选择原则

#### 必须遵循的原则

| 原则             | 说明                                     |
| ---------------- | ---------------------------------------- |
| **高效性** | 优先选择计算速度快、效率高的模型         |
| **准确性** | 确保模型能够准确描述和解决问题           |
| **简洁性** | 在满足要求的前提下，选择相对简单的模型   |
| **创新性** | 在简洁的基础上追求创新——先保证模型能解出问题，再考虑差异化 |
| **实用性** | 模型要有实用性，以能够解决问题有效为原则 |

#### 模型选择三原则（核心指导）

```
┌─────────────────────────────────────────────────┐
│  模型选择三原则（必须严格遵守）                  │
├─────────────────────────────────────────────────┤
│  1. 能用初等方法解决的就不用高等方法             │
│  2. 能用简单方法解决的就不用复杂方法             │
│  3. 能用被更多人看懂、理解的方法                 │
│     就不用只能少数人看懂、理解的方法             │
└─────────────────────────────────────────────────┘
```

#### 模型必须具备的特点

- **数学抽象性**：必须使用数学方法来建立模型，模型要有一定的数学抽象性
- **普遍性**：处理方法要具有一定的普遍性，可以不局限于某个具体问题的解决
- **实用性**：模型要有实用性，以能够解决问题有效为原则，不过分追求高、深、难

#### 谨慎使用的模型

| 模型类型     | 使用建议                                |
| ------------ | --------------------------------------- |
| 神经网络     | 仅在传统方法效果不佳时考虑使用          |
| 机器学习模型 | 如随机森林、XGBoost等，优先尝试传统模型 |
| 深度学习模型 | 仅在处理复杂高维数据时考虑使用          |

#### 推荐的模型类型

| 问题类型 | 推荐模型                     |
| -------- | ---------------------------- |
| 优化模型 | 规划模型、图论模型           |
| 预测模型 | 时间序列、回归分析、灰色预测 |
| 评价模型 | AHP、熵权法、TOPSIS          |
| 分类模型 | 聚类分析、判别分析           |

## ━━━ 第 6 章  文档模板━━━

### 分析文档格式

**必须产出独立的题目分析文档** `题目分析.md`：

**重要**：文档中必须包含完整的数学公式。不管什么题型，写法标准为四段式：**符号定义→公式建立→推导展开→最终形式**。

**通用公式要求**（适用所有题型）：
- 每个子问题独立一节数学模型
- 所有公式用 LaTeX 编写（`$$...$$` 或 `$...$`）
- 公式连续编号（如 `(1)`, `(2)`）
- 所有符号在术语表中有对应条目，禁止出现未定义符号
- 推导链完整：每个公式的上一行为什么能推出下一行，必须有文字说明
- 每个子问题至少 3 个编号公式

**按题型的公式清单**（必须覆盖，缺一不可）：

| 题型 | 必须包含的公式类型 |
|------|-------------------|
| 优化 | 目标函数 + 等式约束 + 不等式约束 + 拉格朗日/KKT条件(如适用) |

每个子问题的数学模型按此结构：

```

#### 示例：优化题

**符号与变量**：

| 符号 | 含义 | 单位 |
|------|------|------|
| $x_{ij}$ | 决策变量：材料 $i$ 是否放入货位 $j$ | 0-1 |
| $f_i$ | 材料 $i$ 的消耗频率 | — |

**目标函数**：
$$\min \quad Z = \sum_{i=1}^n f_i \cdot t_i(x_{ij})$$

**约束条件**：

*容量约束* — 每个货位最多一箱：
$$\sum_{i=1}^n \sum_{k=1}^{q_i} x_{ikj} \leq 1, \quad \forall j \quad (1)$$

*数量约束* — 每种材料全部分配：
$$\sum_{j=1}^S x_{ikj} = 1, \quad \forall i, k \quad (2)$$

*箱型匹配约束*：
$$x_{ikj}=0, \quad \text{if } \text{type}(i) \notin \text{allowed}(j) \quad (3)$$

#### 示例：评价题

**指标标准化**（极差法，正向指标）：
$$r_{ij} = \frac{x_{ij} - \min_j x_{ij}}{\max_j x_{ij} - \min_j x_{ij}} \quad (1)$$

**熵权计算**：
$$e_j = -k \sum_{i=1}^m p_{ij} \ln p_{ij}, \quad p_{ij}=r_{ij}/\sum_i r_{ij}, \quad k=1/\ln m \quad (2)$$

$$w_j = \frac{1-e_j}{\sum_{j=1}^n (1-e_j)} \quad (3)$$

**TOPSIS 综合得分**：
$$D_i^+ = \sqrt{\sum_{j=1}^n w_j(r_{ij} - r_j^+)^2}, \quad D_i^- = \sqrt{\sum_{j=1}^n w_j(r_{ij} - r_j^-)^2} \quad (4)$$
$$C_i = \frac{D_i^-}{D_i^+ + D_i^-} \quad (5)$$

#### 示例：预测题

**GM(1,1) 模型方程**：
$$x^{(0)}(k) + a z^{(1)}(k) = b \quad (1)$$
$$z^{(1)}(k) = 0.5 x^{(1)}(k) + 0.5 x^{(1)}(k-1) \quad (2)$$

**参数估计**（最小二乘）：
$$[a, b]^T = (B^T B)^{-1} B^T Y \quad (3)$$

**预测还原**：
$$\hat{x}^{(0)}(k+1) = (1-e^a)\left[x^{(0)}(1)-\frac{b}{a}\right] e^{-ak} \quad (4)$$

**误差检验**：
$$\text{MAPE} = \frac{100\%}{n}\sum_{k=1}^n \left|\frac{x^{(0)}(k)-\hat{x}^{(0)}(k)}{x^{(0)}(k)}\right| \quad (5)$$

#### 示例：仿真题

**状态方程**：
$$\frac{dT(t)}{dt} = \frac{1}{RC}(T_{\text{out}} - T(t)) + \frac{\eta}{C} P(t) \quad (1)$$

**隐式欧拉离散化**：
$$\frac{T_{n+1} - T_n}{\Delta t} = \frac{1}{RC}(T_{\text{out}} - T_{n+1}) + \frac{\eta}{C} P_{n+1} \quad (2)$$
$$T_{n+1} = \frac{RC \cdot T_n + \Delta t \cdot T_{\text{out}} + RC \cdot \Delta t \cdot \eta \cdot P_{n+1} / C}{RC + \Delta t} \quad (3)$$

**稳定性条件**：
$$\Delta t \leq \frac{RC}{2} \quad (4)$$

## ━━━ 第 9 章  公式可追溯原则（新增）━━━

### 9.1  为什么需要这个原则

ProblemAnalysis.md 中的每个编号公式最终必须回答两个问题：
1. **谁实现它？** — 编程手需要在 solver 代码中产出该公式的数值结果，还是论文手只在论文中推导展示？
2. **实现了没有？** — S5 运行前必须确认所有"需要实现"的公式都有对应代码。

没有这个标注，编程手不清楚哪些公式要写代码、论文手不清楚哪些公式要引用、审稿手不清楚哪些公式应该被实现——三个角色各自猜测，必然出现"论文写了公式但代码没做"的脱节。

### 9.2  公式角色标注规则

ProblemAnalysis.md 中每个编号公式的紧邻下方或上方，必须用以下格式标注其角色：

```
\[
\min \; \mathbb{E}[T] = \sum_i \tilde{f}_i \bar{t}_i + T_{\text{load}} \tag{2}
\]
<!-- 角色A: 编程手实现 → greedy_assignment() 目标函数 -->
```

| 角色 | 标记 | 义务 | 编程手行为 |
|------|------|------|-----------|
| **角色A** | `<!-- 角色A: 编程手实现 → [函数名] -->` | 必须被求解器实现并产出数值 | 在指定函数中实现，产出数值到 results/ |
| **角色B** | `<!-- 角色B: 论文手推导，无需代码实现 -->` | 仅在论文中展示推导过程 | 不实现，不报错，不占用 S5 工时 |

**禁止**：
- ❌ 不标注角色（审稿手无法判断该公式是否应该被实现）
- ❌ 角色A 标注了但没写目标函数名（编程手不知道在哪实现）
- ❌ 所有公式都标角色A（实际上推导链中的中间公式只有论文展示价值）

**正确示例**：
```latex
\min \; \mathbb{E}[T] = \sum_i \tilde{f}_i \bar{t}_i + T_{\text{load}} \tag{2}
<!-- 角色A: 编程手实现 → greedy_assignment() 计算 et -->
```

```latex
\Delta T = T_{\text{SC}} - T_{\text{DC}} = t(s_{\text{out}}\to 0)+t(0\to s_{\text{in}})-t(s_{\text{out}}\to s_{\text{in}}) \tag{13}
<!-- 角色B: 论文手推导，无需代码实现（DC节省公式的代数推导，不是求解目标） -->
```
