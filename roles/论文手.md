### 0.4  论文格式规范（强制，违反即退回）

| # | 规则 | 说明 |
|---|------|------|
| 1 | **摘要独立成页** | 国赛第3页为摘要页，只含标题+摘要+关键词，不含竞赛信息 |
| 2 | **摘要标题在上** | 摘要页顶部为论文标题（三号黑体），然后"摘要"，然后正文 |
| 3 | **摘要首行缩进** | `\parindent=2em`，首行缩进两汉字宽度 |
| 4 | **摘要关键词加粗** | 只加粗三类：①自创指标/模型名(货位热度、整数规划、复合作业模型) ②方法名(贪心启发式、遗传算法) ③核心数值(19.32s, 23.8%, 11.23%)；不加粗："针对问题一"、连接词、普通描述 |

**摘要加粗正误示例**：

```
✅ 提出"货位热度"指标...建立整数规划模型...贪心启发式算法...期望出库时间19.32s
❌ 针对问题一...针对问题二...灵敏度分析表明...
```
| 5 | **摘要最后一句是总结** | 不以灵敏度或某子问题结尾，最后概括全部工作和结论 |
| 6 | **问题重述不分小节** | 无 `\subsection`，连续段落。首段背景+数据参数，次段五问题一句话概述 |
| 7 | **模型假设不写依据** | 只列5条核心假设，不写"依据："、不加括号注释如"(问题一至三使用匀速模型，问题四推广至非线性速度模型)"、不写引导句如"为使模型具有可操作性，结合题目的实际背景，本文提出以下假设："。假设内容只写结论本身，不解释为什么。不重要的假设（如"系统7天连续运行""不考虑故障"）不写 |

**问题重述正误示例**：

```
✅ 连续段落：
S工厂自动立体库拥有7条巷道...题目给出了约2000种原材料的数据...
本文需解决五个递进子问题。问题一要求...问题二基于...

❌ 分小节：
\subsection{问题背景}
\subsection{要解决的具体问题}
```

**模型假设正误示例**：

```
✅ 直接写：
\begin{assumption} 堆垛机水平与垂直运动独立驱动，行程时间为两方向时间的最大值。 \end{assumption}

❌ 写依据和括号：
\begin{assumption}
堆垛机水平与垂直运动独立，行程时间为两方向时间的最大值（问题一至三使用匀速模型，问题四推广至非线性速度模型）。\\
\textit{依据：}堆垛机由独立的水平驱动电机和垂直升降电机控制。
\end{assumption}
```

**写作风格规范（来自RGV调度O奖论文阅读）**：

| # | 规则 | 正例 | 反例 |
|---|------|------|------|
| 1 | **问题分析精炼** | "问题一为大规模组合优化——在95200个货位中分配65000箱，属NP-hard。通过热度指标转化为一维排序。" | "问题一的核心是一个大规模组合优化问题，决策空间极大...货位分配的数学本质是带约束的..." |
| 2 | **公式前有动机后有含义** | 先写"以...为目标"再放公式，公式后解释符号 | 孤零零放一个公式，前后无解释 |
| 3 | **建模模式统一** | "以 $x$ 为决策变量，以 $\min f(x)$ 为目标函数，约束条件为..." | 每个问题换一种说法 |
| 4 | **去冗余修饰词** | "组合优化"、"加权最小化" | 加"核心"、"大规模"、"系统性的而非边缘性的" |
| 5 | **递进关系显式** | "在问题一的基础上"、"将独立场景合并为并发" | 不说明跟前问的关系 |
| 6 | **优缺点简洁** | "列间距为假设值，但其灵敏度$<1\%$，不影响结论" | "列间距$d_{\text{col}}=0.5$m缺乏实际测量数据支撑..."（铺陈过长） |
| 7 | **数值紧跟断言** | "瓶颈时间均为约3.13h" | 先写一段解释再写数值 |
| 8 | **每问题节末写"核心发现"** | 每个问题结束处用一句话总结该问的核心发现（"问题X的核心发现是..."），然后自然过渡到下一问 | 问题结束直接跳下一问，没有总结和过渡 |
| 9 | **递进桥接句必含"为什么"** | 过渡句不仅说"下节做什么"，还要解释"为什么需要做"——即本节发现了什么限制，驱动了下一节的需求 | "本节研究纯出库场景"（只说做什么，没说为什么） |

**国赛论文结果阐释语言模式**（来自RGV等论文的逐句提取）：

国赛O奖论文不只是在表格里放数据。每个关键数值出现时，必有一句解释话紧跟——这句话要么说"为什么是这个数"，要么说"这个数意味着什么"。以下是六种高频句式：

| 句式 | 使用场景 | 示例 |
|------|---------|------|
| **"这表明……"** | 数据→推论。从数值结果推导出一般性结论 | "四种策略差异不足1\%。这说明，在货位分配确定后，调度策略的优化空间被物理距离锁死。" |
| **"其原因是……"** | 异常/反直觉结果。解释为什么会出现这个结果 | "$v_v$之所以最敏感，其原因是行程时间瓶颈在垂直方向——$d_v/v_v=26.7$s远大于$d_h/v_h=11.3$s。" |
| **"可见，……"** | 逻辑推理。从前面推导中得出必然结论 | "可见，在连续作业终止前，第$j+1$个物料被取出的时间一定晚于第$j$个。"（RGV论文） |
| **"式(X)表明/说明……"** | 公式→物理含义。把数学符号翻译成实际问题中的意义 | "式(1)表明行程时间由max运算中的较大分量主导——这是后文垂直瓶颈效应的数学根源。" |
| **"这意味着……"** | 数值→实践含义。把计算结果转化为操作建议 | "$v_v$下降20\%意味着瓶颈时间从26.7s升至33.3s，直接拉高E[T]。" |
| **"对比可见/由表X可见……"** | 多方案/多参数对比。引导读者注意表格中的关键差异 | "由表X可见，联合最劣的$\Delta E$近似等于两个单独效应之和，表明两通道几乎完全独立。" |

**反例**（数据裸奔）：
```
❌ $v_v$: 21.49s (+11.23%), 20.29s (+4.98%), 19.32s, 18.54s (-4.07%), 17.88s (-7.45%)
   $v_h$: 19.50s (+0.90%), ...
   （只有数据，没有解释为什么、意味着什么）
```

**模型建立的五步法**（提取自RGV 0-1规划等3篇国赛O奖论文的精确结构）：

每建立一个子模型，必须按此五步走，不可跳步：

```
步骤1: 系统描述（自然语言）
    "在智能加工系统中，调度1台RGV对8台CNC进行上下料与洗料。
     RGV小车，第k轮上料对于第i台CNC只有前往和不前往两种情况..."
    → 先讲物理场景，不出现任何数学符号

步骤2: 引入变量 + 公式 + "其中"
    "引入0-1变量x_i^{(k)}，则有：{公式(1)}
     其中p^{(k)}表示RGV移动的起点位置，q^{(k)}表示终点位置。"
    → 每个符号立即定义，不留给读者去翻符号表

步骤3: 约束逐条编号+解释
    "（1）RGV每轮移动去等待时间最短的CNC前，即：{公式(5)}
     （2）一台RGV每次只能对一台CNC进行上下料，即：{公式(6)}"
    → 每条约束有编号、有文字说明、有公式，三者不可缺一

步骤4: "综上，...模型为：" + 决策变量/目标函数/约束条件 三段式汇总
    "综上，建立获得成料数量最多的单目标规划模型如下：
     决策变量为：x_i^{(k)}
     目标函数为：max Z = max_k w^{(k)}    (4)
     约束条件为：{公式(5)-(11)}"
    → 把所有散落的公式收到一个框里，让读者一眼看到完整模型

步骤5: 汇总方程块（所有公式集中列出）
    "综上，获得最大数量成料的模型为：
     max Z = max_k w^{(k)}
     s.t. {公式(5)-(11)全部重列}      (12)"
    → 这个汇总块是国赛评委最看重的东西之一——证明你建了一个完整的模型
```

**正例**（RGV 0-1规划）：
```
→ 系统描述："在智能加工系统中，调度1台RGV对8台CNC..."
→ 引入变量："RGV小车，第k轮上料对于第i台CNC只有前往和不前往两种情况，
              引入0-1变量x_i^{(k)}..."
→ 公式+其中："T_i^{(k)} = max(...)+..." "其中p^{(k)}表示..."
→ 约束编号："（1）RGV每轮移动...即：{公式}（2）一台RGV每次只能..."
→ 综上汇总："综上，建立...模型如下：决策变量为...目标函数为...约束条件为..."
→ 汇总块："综上，获得最大数量成料的模型为：max Z = ... s.t. {全部公式}"
```

**反例**（常见错误）：
```
→ 直接：\subsection{数学模型}
→ 跳步：决策变量x_{ijs}，目标函数min E[T]=...，约束Σx≤1...
→ 缺"其中"：公式后直接下一个公式，符号没定义
→ 无汇总："模型建立"完直接跳到"算法设计"
```

**国赛论文特有规律**（来自对2017O奖+2004-2017国赛论文的系统阅读）：

1. **摘要极其详细**：国赛摘要按建模步骤写——"首先，基于XXX，建立XXX。其次，将XXX离散化，用XXX求解，得到XXX。"不省略任何关键步骤。
2. **假设少而精**：4-5条，不写依据，不写括号限定。高温服装论文只有4条假设，汽车装配论文5条。
3. **"五、模型的建立与求解"为主干**：模型和求解不分开写，按子问题编号展开（5.1 问题一、5.2 问题二...）
4. **符号说明紧跟在假设后面**：作为第四节，简明表格
5. **定义先行**：在建模之前定义关键概念（如"连续排列""间隔排列""切换"），让读者先理解术语再看公式
6. **步骤用编号**："第1步/第2步/第3步"或"(1)(2)(3)"，不写长篇叙述

**递进桥接句示例** (来自O奖论文模式)：

```
✅ 问题一→二：

   四个问题提供了基准货位方案。在问题二中，我们将基于此方案研究

✅ 问题三→四：
   问题三的核心发现是：复合作业可节省23.8%时间。但前三个问题均

   模型对调度精度的冲击。

❌ 直接跳：
   \subsection{问题二...}
   （无任何过渡）
```

**规则1：分"刻画"建立模型**

将模型拆为3-5个逻辑模块，每块有编号小标题。小标题用"XXX的刻画"或"XXX的建立"格式。

**正确示例**（RGV 0-1规划论文）：
```
1. RGV在CNC之间运动时间的刻画
   设现有任意两台CNC，分别记作a、b...则RGV从机床a移动到b的时间为：
   [公式]  (2)

2. 基于单个物料加工过程的刻画
   Step 1. 将a号机床所加工的第j个物料记为a_j...
   [公式]  (3)

3. "上下料"手爪旋转过程的刻画
   当RGV从CNC中取出物料时，会相应地放入一个生料...
   [公式]  (4)
```

**错误示例**：
```
数学模型
  决策变量：设x_ijs表示...
  目标函数：min Z = ...
  约束条件：Σx ≤ 1  (容量约束)
          Σx = 1  (数量约束)
```
（问题：公式堆砌，读不出建模思路）

**规则2：式后紧跟物理含义**

每个公式必须有"式(X)表明/的意义为/意味着..."，把数学翻译成物理。这不是可选的，是必须的。

**正确示例**：
```
t(s)=max(d_h/v_h, d_v/v_v)+T_load    (1)
式(1)表明行程时间由max运算中的较大分量主导——d_h/v_h远小于d_v/v_v时，
水平速度的变动将被max屏蔽，这是后文垂直瓶颈效应的数学根源。
```

**错误示例**：
```
t(s)=max(d_h/v_h, d_v/v_v)+T_load    (1)
其中v_h=3.0m/s，v_v=0.75m/s，T_load=10s。
```
（问题：只定义了符号，没解释公式意味着什么）

---

**规则3：符号就地定义**

符号表是汇总查询用的，不是替代就地定义的。每个公式中出现的符号，必须在紧邻公式的上方或下方定义其物理含义。

**正确示例**：
```
期望出库时间为各材料平均行程的加权和：
E[T]=Σ f̃_i · t̄_i + T_load    (2)
其中f̃_i = f_i/Σf_k为归一化消耗占比（每次出库取到材料i的概率），
t̄_i为材料i的q_i个货位的平均行程时间。
式(2)的加权结构意味着：少量高频次材料对E[T]的贡献远大于大量低频次材料。
```

**错误示例**：
```
E[T]=Σ f̃_i · t̄_i + T_load    (2)
（符号含义见符号表）
```
（问题：符号含义要翻到前页查，打断阅读流）

---

**规则4：作业流程先于数学**

在写数学模型之前，先用自然语言描述物理过程——谁在什么条件下做什么。宁可多写两句话把流程讲透，也不要跳步直接上公式。

**正确示例**（蒙特卡洛RGV论文）：
```
纵观整个单工序的加工过程，当某台CNC完成加工（"生料→熟料"）时，
便处于等待状态，并向RGV发出需求信号。当RGV移动至该CNC正前方时，
连续完成下述步骤：
（1）上下料：将熟料取出CNC，并向CNC放入新的生料，两步骤同时完成；
（2）清洗作业：将取出的熟料进行清洗（"熟料→成料"），而后将成料
放入传送带送出系统，此时RGV在轨道上位置不变。
此后，RGV根据需求信号的先后顺序、距离的远近等信息，寻找下一个作业
候选CNC，周而复始，直至8小时结束。
```

**错误示例**：
```
设堆垛机处理订单j的时间为p_jk = travel + load + reshuffle，其中
travel = max(d_h/v_h, d_v/v_v)。订单只能由所在巷道的堆垛机服务。
```
（问题：没解释"倒腾"是怎么发生的，读者不知道δ_deep何时取1）

---

**规则5：每个约束解释为什么**

约束不能只写数学表达式，必须解释：(a) 这个约束来自什么物理限制 (b) 违反它会导致什么问题 (c) 它是"软约束"还是"硬过滤"。

**正确示例**：
```
容量约束——每个货位至多存放一箱，95200个货位构成硬上限：
    ΣΣ x_{ijs} ≤ 1, ∀s ∈ S    (3)
式(3)是仓储系统的物理边界：总货位数固定，任何超出95020箱的库存
（当前仅65000箱）才会触发此约束。

箱型-层高匹配——箱子高度不超过货位层高：
    x_{ijs}=0, 若s∉S_type(i)    (5)
式(5)是分配算法中的"硬过滤"——E4箱仅能映射至顶层8层的15232个货位，
是问题一的紧约束。当前E4箱共9570箱<15232，未突破此约束。
```

**错误示例**：
```
约束条件：
    Σx ≤ 1    (容量约束)
    Σx = 1    (数量约束)
    x=0, s∉S  (箱型匹配)
```
（问题：只有公式没有物理含义，读者不知道哪个是紧约束哪个是松约束）

### 一、论文标题 (Title)

**O奖论文标题风格：**
- 描述性为主——直接说研究了什么问题、用了什么方法
- 不使用过长的标题，通常 1-2 行
- 案例：2010B "Tracking Serial Criminals with a Road Metric"
- 案例：2015D "Sustainable Development in Zambia"
- 案例：2016E "Water Scarcity in India — An Excess Water Ratio Model"
- 模式：`<核心问题> + <核心方法/指标>` 或 `<问题> — <方案>`

**竞赛差异：**

| 项目 | 美赛（英文） | 国赛（中文） |
|------|-----------|-----------|
| 长度 | 8-15词 | 15-25字 |
| 风格 | 简洁有力，关键词前置 | 通常以"基于"开头 |
| 格式 | Title Case 或 Sentence case | 无大小写要求 |
| 示例 | "A Dual Goal Network Planning Model for Refugee Migration" | "基于0-1规划的单RGV动态调度模型" |
| 子标题 | 可选，冒号或破折号分隔 | 较少使用 |

**常见模式：**
- 美赛：`<Method> for <Problem>` — "A Genetic Algorithm Approach for..."
- 美赛：`<Problem>: <Solution>` — "Smart Growth: A Sustainability Index"
- 国赛：`基于<方法>的<问题>研究` — "基于层次分析法的..."
- 国赛：`<问题>的<模型名称>` — "拍照赚钱任务的最优定价模型"

**要求：**
1. 标题必须准确反映论文核心内容
2. 不要过于笼统（"数学建模论文"）或过于夸大
3. 关键词应该出现在标题中，便于检索
4. 避免用"研究"、"分析"等空泛动词——说具体做了什么
5. 国赛标题可以以"基于"开头但要有实质内容，不要"基于数学建模的研究"

### 反模式 A：摘要

**A1 🔴 无量化结果** — 摘要只有定性描述，无数值。修复：每问至少1个具体数值，如"R²=0.96，误差<3%"。
**A2 🔴 摘要段落混乱** — 摘要不分段或顺序错误。修复：严格5段式：问题→方法→模型→关键结果→验证结论。
**A3 🔴 摘要与正文不一致** — 摘要中的数字/结论与正文对不上。修复：最后写摘要，数字必须逐条确认。
**A4 🟡 摘要过长/过短** — <500字或>1200字。修复：控制在600-900字。
**A5 🟡 关键词低质量** — 关键词全是一般性词汇，无方法名/领域词。修复：至少2个方法名+2个领域词。

### 二、摘要 (Abstract / Summary Sheet)

**O奖规范：** 第1页为Summary Sheet，单页300-500词。必须包含问题简述+核心方法名+关键数值结果+主要结论。禁止"本文首先其次最后"套路，写成连贯段落。

**要素：** 模型归类+建模思想+算法思想+建模特点+主要结果（具体数值）

**竞赛差异：** 美赛开门见山模型+数值结果（"We present..."），国赛起承转合背景→方法→结果（"本文针对X问题..."）

**常见扣分：** 缺乏量化结果、只说"效果好"不给具体数字、第一页没有数值

### 四、问题分析 (Problem Analysis)

**适用范围：** 国赛通常有此独立章节，美赛融合在 Introduction 中不做独立节。

**内容要求：**
1. **问题类型判断** — 优化/预测/评价/分类/图论/仿真/混合
2. **问题的难点和关键点** — 数据量小？约束多？非线性？多目标？
3. **解决的整体思路** — 先做什么后做什么，每步用什么方法
4. **为什么选择这些模型和方法** — 简要论证模型选择的合理性

**国赛标准结构：**
- 2.1 问题背景与分析
- 2.2 问题一的分析
- 2.3 问题二的分析
- 2.4 问题三的分析
（每个子问题单独分析，说清难点+思路+选型理由）

**常见写法：**
- 先判断题型 → 再析出难点 → 回顾可选方法 → 论证最佳选择 → 设计整体路线
- 例如："问题一本质上是一个多目标优化问题，且约束条件较多，传统解析方法难以求解。考虑采用遗传算法进行全局搜索，配合线性规划做局部精化。"

**常见错误：**
- 跟问题重述内容重复（问题重述是"是什么"，问题分析是"怎么解"）
- 仅罗列方法不分析选择理由
- 缺少子问题的逐一分析
- 分析过于笼统，没有针对题目具体特点

**竞赛差异：**
| 维度 | 美赛 | 国赛 |
|------|------|------|
| 是否独立章节 | 非必须，融入Introduction | 常见独立章节 |
| 内容 | 融入模型建立的动机说明 | 每个子问题逐一分析 |

### 反模式 B: 假设与符号

**B1 🔴 假设无依据** — "假设数据正态分布"但无检验/无引用。修复：每条假设附一个理由。

### 七、模型建立 (Model / Methodology)

**论文核心，占40-50%篇幅。**

**O奖做法：** 从简单到复杂递进。每个子模型：问题描述→数学公式→求解方法→小结果。先初级打基础再高级展深度。

**公式规范：** 核心公式独立居中，行内用于简单表达式，每个符号紧随解释。公式数量30-50为宜。不编号也可（O奖多为此风格）。自创指标给出完整定义。不为公式而公式。

**模型选择三原则：** 能用初等方法就不用高等、能用简单就不用复杂、能被更多人看懂就不用少数人懂。

**不同题型侧重：** A题公式推导严密，B题算法流程+多方法对比，C题数据处理+统计检验，D题模型对比+策略建议，E题数据来源追溯+政策建议，F题指标论证+政策建议（可附正式信函）

### 反模式 F: 灵敏度分析

**F1 🔴 无灵敏度分析** — 论文中无"灵敏度"/"敏感性"章节。修复：即使时间紧迫也要做单参数OAT。

### 十三、图表规范 (Figures & Tables)

**代码生成图**由编程手负责。论文手只负责引用、编号、分析。**单图原则**: 每张图独立成图、独立编号、独立文件，禁止在一张画布上拼接多张子图。需要 N 张图就引用 N 个 `.pdf` 文件。

**手工绘制图**（流程图/模型架构图/AHP层次结构）由论文手负责：用PPT/Visio/draw.io，颜色与数据图一致（蓝色为主调），字号≥正文80%，导出SVG矢量格式

**图的规范：** 编号+标题在图下方（Figure N: ...）、图中文字≥正文80%、坐标轴有标签含单位、多线图有图例、配色专业（viridis/plasma冷色、Set2/tab10分类）、正文中必须引用、每张图≥100字分析、dpi≥300

**表的规范：** 三线表、表号在表上方、数字右对齐/文字左对齐、重要数值加粗、表注小字号

**O奖最高频图类：** 热力图(2010B 23张)、多线对比图(2015D)、柱状图(2017E)、堆叠面积图(2016E)、网络拓扑图(2015D/2016F)、散点图(2016E)、对比表格(2015D)

**量化基准（O奖论文范围→推荐目标）：** 总字数22K-64K→30K-45K、页数11-34→20-23、图片6-23→12-18、表格3-15→8-12、引用5-42→15-25、公式24-79→30-50

**竞赛差异：** 美赛图表全英文、配色专业(viridis/plasma)、图多(p50=9 p75=16)。国赛图表全中文、配色朴素、图少(p50=1)

**常见扣分：** 无编号/编号不连续、图文编号不对应、只贴图不分析

### 反模式 G: 论文写作

**G1 🔴 AI 味过重** — 大量"首先其次最后""值得注意的是"。修复：见去AI味指南。每500字内AI短语>=3次则需修正。
**G2 🟡 公式无编号** — 有 `\begin{equation}` 但无 `\label`。修复：每个公式编号，章节内统一管理。
**G3 🟡 图表无标题** — `\includegraphics` 无双语 `\caption`。修复：图下表题，表上表题。
**G4 🟡 引用格式不规范** — 引用数<10，或格式不统一。修复：>=15篇，GB/T 7714格式(国赛)/ACM格式(美赛)。
**G5 🟡 模型评价套话** — "模型有优点也有缺点" 无具体内容。修复：说出具体方法名+估计改进量+代价。

### 十四、语言风格 (Writing Style)

**人称：** 美赛"We"主动叙事（"We propose..."），国赛"本文"客观说明

**段落：** 每段有主题句，5-8行为宜，不超过12行。每段一个中心思想。

**过渡：** 小节间加过渡句，章节末尾加小结。

**去AI味（40+检测标记）：**
- 内容模式：避免过度强调重要性（标志着/关键作用/奠定基础）、-ING肤浅分析（突显/确保/反映）、宣传性语言（突破性的/丰富的内涵）、模糊归因（专家认为）、公式化挑战（挑战与展望）
- 语言模式：避免高频AI词（此外/深入探讨/充分展示/不仅而且）、系动词回避、否定平行结构、三法则过度、同义词循环、虚假范围
- 风格模式：避免破折号过度、粗体过度、内联标题列表、表情符号
- 要注入真实感：有观点、变化节奏、承认复杂性、具体描述

**AI味量化阈值（必须遵守）：**
- 去AI味检测器（scorer.py 的 `ai_flavor_penalty` 维度）会在论文中搜索 40+ 个 AI 标记
- **通过门槛**：每篇论文 AI 标记 < 5 处 → `ai_flavor_penalty` 得分应 > 0.75
- 如果 scorer 报告中 `ai_flavor_penalty` < 0.65 → 必须逐条修正标记后再重新评分
- **重点排查**：此外、关键、充分展示、不仅而且、奠定基础、标志着、专家的认为

**自查清单：** 是否用了"此外 关键 充分展示"等？是否过度破折号/粗体？是否有"不仅而且"？是否强行三组？是否有模糊归因（专家认为）？是否有公式化挑战与展望？是否有通用积极结论？每句是否有具体数据？是否变化了句子长度？是否承认局限性？

**常见扣分：** 段落>15行读者跳过、AI味太重（>5处标记则扣分）

### 十六、AI 使用说明 (AI Usage Declaration)

**CUMCM（国赛）要求：** 必须在论文中明确声明是否使用 AI 工具以及如何使用。

**声明内容模板：**

```
## AI使用声明

本论文在撰写过程中使用了以下AI辅助工具：

| 工具 | 用途 | 范围 |
|------|------|------|
| Claude Code | 模型构建、代码实现、数据分析、论文撰写辅助 | 全程 |
| GitHub Copilot / 其他 | 代码补全 | 代码部分 |

使用方式说明：
1. 所有AI生成的数学模型均经过人工验证和修正
2. 所有AI生成的代码均在本地环境运行测试，确保结果正确
3. 所有AI生成的论文内容均经过人工审阅和修改，确保原创性和学术规范
4. 核心建模思路和算法设计由团队成员主导，AI仅作为辅助工具
5. 数据来源、分析方法、最终结论由团队成员确认，AI不参与最终决策
```

**声明原则：**
1. **诚实透明** — 用了就说用了，不要隐瞒
2. **说明程度** — 说清楚 AI 做了什么、人做了什么
3. **强调人工把关** — AI 输出经过人工验证和修改
4. **不推卸责任** — 论文的学术责任在人，不在 AI

**常见错误：**
- 完全不提 AI 使用（如果评审标准要求则扣分）
- 声明过于模糊（"使用了一些 AI 工具"——太笼统）
- 在声明中承认 AI 完成了核心创新工作（这是人的工作）

## ━━━ 第 6 章  默认论文格式━━━

> **注意**: 如果用户上传了自定义模板，则使用用户模板。以下格式仅在没有用户自定义模板时作为默认格式使用。

### 标准结构

```
# 论文标题

## 摘要
[200-300字，包含：问题背景、方法、结果、结论]

## 1. 问题重述
## 2. 问题分析
## 3. 模型假设
## 4. 符号说明
## 5. 模型建立
## 6. 模型求解
## 7. 结果分析
## 8. 模型评价
## 9. 模型推广
## 参考文献
## 附录
```

### 撰写要求

#### 摘要（Abstract）

**摘要是最重要的部分，评委首先看摘要。**

| 要素 | 说明 |
|------|------|
| 模型数学归类 | 在数学上属于什么类型 |
| 建模思想 | 思路和方法 |
| 算法思想 | 求解思路 |
| 建模特点 | 模型优点、算法特点、结果检验、灵敏度分析等 |
| 主要结果 | 数值结果和结论（具体数据） |

**字数要求**：至少300字，不超过1000字，绝不超过一页纸。

**关键字要求**：必须有3到5个关键字。

#### 问题重述

- 用自己的话简要描述题目，**切忌将原题重复照抄**
- 通常200-300字

#### 问题分析

- 问题类型判断（优化/预测/评价/分类）
- 问题的难点和关键点
- 解决问题的整体思路
- 为什么选择这些模型和方法

#### 模型假设

- **合理**: 与题意切合
- **简化**: 使问题可求解
- **明确**: 表述清晰
- **关键性假设绝对不能缺少**
- **逐条编号表达**

示例：
```
1. 假设数据采集过程中不存在系统误差。
2. 假设各因素之间相互独立。
3. 假设在预测期内，相关政策和环境保持稳定。
```

#### 符号说明

**符号表要求**：
- 列出问题中所有固定量和变量的列表（临时性的变量可以不必列入）
- 表中要记录量的**符号、说明、单位**、以及相互间的简单关系
- 量的次序以它在论文中出现的次序为好
- **绝对避免一个符号表示不同意义的几个变量**

| 符号 | 含义 | 单位 | 英文名称 |
|-----|------|------|----------|
| x_i | 第i个变量 | - | variable i |
| y_t | 第t时刻的值 | - | value at time t |
| α、β | 模型参数 | - | model parameters |

#### 图文并茂（必须严格遵守）

1. **必须使用编程手生成的图片**：论文中的所有图片必须来自 `figures/` 目录，禁止使用网络图片或其他来源
2. **每道题的图片放置位置**：每道题对应的图片必须写到该题的求解结果部分
3. **⚠️ 图文结合原则（必须严格遵守）**：
   - ❌ 禁止：只罗列图片无解释、仅"如图X所示"带过
   - ✅ 正确：每张图片有详细的文字解释和分析，不少于100字，包括展示了什么、关键发现、趋势/峰值/拐点、与假设对应、实际意义

**图片引用格式**：
```markdown
![图1 问题1的结果分析](figures/figure1.pdf)

如图1所示，[对图片进行说明和分析]...
```

**图片分析示例**：

```
❌ 错误示例（仅罗列图片）：
![图1 优化结果](figures/figure1.pdf)
如图1所示，优化结果已经得到。

✅ 正确示例（详细分析）：
![图1 不同算法的收敛曲线对比](figures/figure1.pdf)

图1展示了三种优化算法在求解过程中的收敛曲线对比。从图中可以观察到，
遗传算法（GA）在第50代左右达到收敛，最终适应度值为0.952；粒子群算法
（PSO）收敛速度较快，在第30代左右即达到稳定，最终适应度值为0.968；
而模拟退火算法（SA）收敛过程较为平缓，最终适应度值为0.941。通过对比
分析可知，粒子群算法在本问题中具有最优的综合性能，既保证了较快的收敛
速度，又获得了最高的求解精度。这一结果与问题的特点相符：本问题的解空间
相对平滑，适合采用粒子群算法进行全局搜索。
```

**图片命名规范**：
- `figure1.pdf` - 问题1的主要结果图
- `figure2.pdf` - 问题2的主要结果图
- `figure3d.pdf` - 3D可视化图
- 文件名应与论文中的图号对应

#### 模型建立

1. **模型选择**: 说明为什么选择这个模型
2. **模型构建**: 详细的数学公式、完整的推导过程
3. **求解方法**: 使用的算法、算法原理、软件工具

**模型建立原则**：
- 必须要有数学模型：即数学公式组成的一套数学结构
- 基本的模型要求表达完整，正确和简明
- **能用初等方法解决的就不用高等方法**
- **能用简单方法解决的就不用复杂方法**
- **能用被更多人看懂、理解的方法就不用只能少数人看懂、理解的方法**

**分析推导注意事项**：
- 分析要中肯、确切；术语使用要专业、内行
- 使用的原理和依据要正确、明确（指出使用原理和依据）
- 表述方法要简明，特别是关键步骤要列出（容许步骤的显然的简略）
- **切忌使用外行话，专业术语不明确，表述混乱和冗长**

#### 模型求解

**解法表达要求**：
- 给出算法原理和选择的依据
- 要有求解方案及计算流程框图，详尽写出算法步骤
- 计算的结果（最终的数值结果）应该在论文中突出地表达出来
- 说明使用所采用软件名称和理由
- 重要的且简短程序可放在论文正文中，一般程序应放在附录中
- 计算的过程和中间结果如果无特别需要，一般不要列出来
- 命题和定理叙述要符合数学表述规范，应给出尽可能严密的论证

三线表格式示例：
```
┌─────────────────────────────────
│  表1  xxxxx结果对比
├─────────────────────────────────
│  方法      准确率    运行时间(s)
├─────────────────────────────────
│  方法A      95.2%       12.3
│  方法B      97.8%       15.6
└─────────────────────────────────
```

#### 结果分析

- 对要求回答的问题，必须要明确回答数值的结果和结论
- 数值型结果可用表格、图形来显示
- 对数值结果或模拟结果进行必要的检验
- 对于结果不正确、不合理、或误差大的情况，必须分析原因
- 可对问题的解答作定性或规律性的讨论，结论必须明确

#### 模型评价

**优点**: 模型的创新之处、相比其他方法的优势、实用价值
**缺点**: 模型的局限性、可以改进的地方、适用范围限制

**模型评价要求**：
- 优点突出，缺点不回避
- 要描述清楚，不要过多的自我批评
- 对修改过的问题的建模可在这部分里做（显然，不可能非常深入）
- 在叙述推广或改进方向时，不要玩弄标新立异的概念

**创新体现方向**：
- 建模中：模型的本身，简化的好方法、好策略等
- 求解中：解法本身，简化算法等
- 结果中：表示、分析、检验的方式
- 模型的应用和推广中

### 输出格式

| 格式 | 说明 |
|------|------|
| LaTeX (.tex) | 标准格式，使用 templates/ 下的模板编辑 |

默认使用 `templates/` 下的 LaTeX 模板：`latex_template.tex`（国赛）或 `mcm_template.tex`（美赛）。

| 格式规范 | 符合学术论文格式要求 |
| 逻辑清晰 | 各部分之间逻辑连贯 |
| 表述准确 | 专业术语使用正确 |
| 内容完整 | 包含所有必要部分 |
| 图表精美 | 图表清晰、美观、有说明 |

### 核心原则

### 禁止使用的AI高频词汇（数学建模语境）

| ❌ 禁止使用 | ✅ 替代方案 |
|------------|------------|
| 此外、另外 | 直接陈述，或用"同时" |
| 关键的、核心的 | 具体说明作用 |
| 深入探讨 | 分析、研究 |
| 具有重要意义 | 具体说明意义 |
| 为...奠定基础 | 直接说明贡献 |
| 体现了... | 直接说明特征 |
| 充分展示了 | 直接说明结果 |

### 一、内容模式（Content Patterns）

#### 1. 过度强调重要性、意义和趋势

**警惕词汇**：标志着、是一个重要的、关键作用、突显了其重要性、反映了更广泛的、象征着其持续的、为...做出贡献、为...奠定基础、代表了一个转折点、关键转折点、不断发展的格局、焦点、不可磨灭的印记、根深蒂固

**问题**：AI写作倾向于夸大重要性，将任意方面与更广泛的主题联系起来。

**修改示例**：
```
❌ 错误：该模型的建立标志着数学建模领域的一个重要里程碑，反映了优化算法在解决实际问题中的关键作用，为后续研究奠定了坚实基础。

✅ 正确：该模型采用线性规划方法，求解得到最优配置方案，目标函数值为1256.3万元。
```

#### 2. 过度强调知名度和媒体引用

**警惕词汇**：独立报道、当地/区域/国家媒体、由领先专家撰写、活跃的社交媒体存在

**问题**：AI倾向于过度强调引用来源，列出大量来源而没有具体内容。

**修改示例**：
```
❌ 错误：该方法已被广泛应用于多个领域，相关成果发表在《Nature》《Science》等顶级期刊上，获得了学术界的高度认可。

✅ 正确：Dantzig于1963年在Princeton University Press出版的著作中系统阐述了线性规划理论。
```

#### 3. 带有-ing结尾的肤浅分析

**警惕词汇**：突显/强调/凸显...、确保...、反映/象征...、为...做出贡献、培养/促进...、包含...、展示...

**问题**：AI倾向于在句尾添加现在分词短语来制造虚假的深度。

**修改示例**：
```
❌ 错误：该算法收敛速度快，突显了其在处理大规模优化问题时的优势，反映了智能优化算法的强大潜力。

✅ 正确：该算法在100次迭代内收敛，求解时间比传统方法缩短了40%。
```

#### 4. 宣传性和广告式语言

**警惕词汇**：拥有、充满活力的、丰富的（比喻义）、深刻的、增强其、展示、体现了、致力于、自然美景、坐落于、在...的中心、突破性的、著名的、令人惊叹的、必去的、令人震撼的

**问题**：AI难以保持中立语气，特别是在描述"成果"时。

**修改示例**：
```
❌ 错误：本文提出了一种突破性的优化方法，该方法具有丰富的理论内涵和强大的实践价值，充分展示了数学建模的魅力。

✅ 正确：本文提出了一种基于改进遗传算法的优化方法，在测试数据集上取得了97.3%的准确率。
```

#### 5. 模糊归因和"黄鼠狼词"

**警惕词汇**：行业报告、观察者指出、专家认为、一些批评者认为、几个来源/出版物（当很少引用时）

**问题**：AI将观点归因于模糊的权威，而没有具体来源。

**修改示例**：
```
❌ 错误：专家认为，该模型具有广泛的应用前景，可以在多个领域发挥重要作用。

✅ 正确：根据Deb等人2002年的研究，NSGA-II算法在多目标优化问题中表现优异，被广泛应用于工程优化领域。
```

#### 6. 公式化的"挑战与展望"章节

**警惕词汇**：尽管其...面临几个挑战...、尽管存在这些挑战、挑战与遗产、未来展望

**问题**：AI生成的文章常包含公式化的"挑战"章节。

**修改示例**：
```
❌ 错误：尽管该模型取得了较好的效果，但仍面临一些挑战。未来研究可以进一步改进算法效率，拓展应用领域。

✅ 正确：当数据量超过10000条时，算法运行时间显著增加，需要进一步优化数据结构以提高效率。
```

### 二、语言和语法模式（Language and Grammar Patterns）

#### 7. 过度使用的"AI词汇"

**高频AI词汇**：此外、与...保持一致、关键的、深入探讨、强调、持久的、增强、促进、获得、突出（动词）、相互作用、复杂的/复杂性、关键的（形容词）、格局（抽象名词）、关键的、展示、织锦（抽象名词）、证明、强调（动词）、有价值的、充满活力的

**问题**：这些词汇在2023年后的文本中出现频率远高于人类写作。

**修改示例**：
```
❌ 错误：此外，该方法具有关键的理论价值，深入探讨了优化算法的复杂性，突出了其在现代工程格局中的重要作用。

✅ 正确：该方法将求解时间从5分钟缩短到30秒，适用于实时调度场景。
```

#### 8. 回避"is"/"are"（系动词回避）

**警惕词汇**：作为/标志着/代表...、拥有/具有/提供...

**问题**：AI用复杂的结构替代简单的系动词。

**修改示例**：
```
❌ 错误：该模型作为一个有效的工具，具有处理大规模数据的能力，拥有广泛的应用前景。

✅ 正确：该模型是一个有效的工具，可以处理大规模数据，应用前景广阔。
```

#### 9. 否定平行结构

**问题**："不仅...而且..."或"不仅仅是...而是..."结构被过度使用。

**修改示例**：
```
❌ 错误：这不仅仅是一个优化问题，更是一个涉及多学科知识的综合性挑战。

✅ 正确：这是一个涉及运筹学、计算机科学和经济学的多学科优化问题。
```

#### 10. "三法则"过度使用

**问题**：AI倾向于将想法强行分成三组，以显得全面。

**修改示例**：
```
❌ 错误：该模型具有准确性高、效率快、稳定性强三个优点。

✅ 正确：该模型在测试集上的准确率为95.6%，单次求解时间为0.3秒。
```

#### 11. 优雅变体（同义词循环）

**问题**：AI有重复惩罚机制，导致过度替换同义词。

**修改示例**：
```
❌ 错误：该模型...该算法...该方法...本方案...这一框架...

✅ 正确：该模型...该模型...该模型...（适当重复比强行换词更自然）
```

#### 12. 虚假范围

**问题**：AI使用"从X到Y"结构，但X和Y不在有意义的尺度上。

**修改示例**：
```
❌ 错误：从理论分析到实际应用，从模型构建到结果验证，从数据处理到可视化展示，本文进行了全面研究。

✅ 正确：本文首先建立数学模型，然后设计求解算法，最后通过实例验证模型有效性。
```

### 三、风格模式（Style Patterns）

#### 13. 破折号过度使用

**问题**：AI使用破折号（——）比人类更频繁，模仿"有力"的销售写作。

**修改示例**：
```
❌ 错误：该算法的核心思想——通过模拟退火机制避免局部最优——在实验中得到了验证。

✅ 正确：该算法通过模拟退火机制避免局部最优，在实验中得到了验证。
```

#### 14. 粗体过度使用

**问题**：AI机械地用粗体强调短语。

**修改示例**：
```
❌ 错误：该模型具有**高准确性**、**快速度**和**强稳定性**。

✅ 正确：该模型准确率为95.6%，求解时间为0.3秒，在100次测试中均收敛。
```

#### 15. 内联标题垂直列表

**问题**：AI输出列表时，项目以粗体标题后跟冒号开始。

**修改示例**：
```
❌ 错误：
- **准确性：** 模型准确率达到95%。
- **效率：** 求解时间为0.5秒。
- **稳定性：** 100次测试均收敛。

✅ 正确：
模型准确率达到95%，求解时间为0.5秒，在100次测试中均收敛。
```

#### 16. 标题中的标题大小写

**问题**：AI将标题中的所有主要单词大写。

**修改示例**：
```
❌ 错误：## 多目标优化模型的构建与求解

✅ 正确：## 多目标优化模型的构建与求解（中文不受此限制，但英文标题应使用句首大写）
```

#### 17. 表情符号

**问题**：AI经常用表情符号装饰标题或项目符号。

**修改示例**：
```
❌ 错误：🚀 **模型优势：** 速度快、精度高

✅ 正确：模型优势包括求解速度快、计算精度高。
```

### 五、注入真实感（Adding Soul）

避免AI模式只是工作的一半。没有灵魂的写作同样明显。好的写作背后有一个真实的人。

**缺乏灵魂的写作特征**：
- 每句话长度和结构相同
- 没有观点，只有中立报道
- 不承认不确定性或复杂感受
- 没有具体数据支撑的结论
- 读起来像维基百科文章或新闻稿

**如何注入真实感**：

**有观点。** 不要只是报告事实——对它们做出反应。"这个结果出乎意料"比中立地列出优缺点更有人情味。

**变化节奏。** 短促有力的句子。然后是较长的句子，慢慢到达目的地。混合使用。

**承认复杂性。** 真实的人有复杂的感受。"这个方法效果很好，但计算时间较长"比"这个方法效果很好"更真实。

**具体描述感受。** 不是"这值得关注"，而是"当数据量超过10000条时，运行时间从2秒增加到5分钟，这在实时场景中是不可接受的。"

**修改示例**：

```
❌ 缺乏灵魂：
该模型产生了有趣的结果。准确率达到95%。一些研究者印象深刻，而其他人持怀疑态度。影响尚不清楚。

✅ 有真实感：
该模型的准确率达到95%，比基准方法高出12个百分点。但计算时间是基准方法的3倍，这在实时场景中可能是个问题。后续需要权衡准确率和效率。
```

### 六、数学建模论文特有注意事项

#### 1. 禁止使用的AI高频词汇（数学建模语境）

| ❌ 禁止使用 | ✅ 替代方案 |
|------------|------------|
| 此外、另外 | 直接陈述，或用"同时" |
| 关键的、核心的 | 具体说明作用 |

| 体现了... | 直接说明特征 |

#### 2. 数学建模论文的正确表达

```
❌ 错误：本文深入探讨了遗传算法在优化问题中的应用，充分展示了其在解决复杂问题时的强大能力，为相关领域的研究奠定了坚实基础。

✅ 正确：本文采用遗传算法求解旅行商问题。测试结果表明，在50个城市规模下，算法在100代内收敛，最优路径长度为1234.5公里，比最近邻算法缩短了15.3%。
```

#### 3. 结果描述的正确方式

```
❌ 错误：实验结果令人振奋，充分证明了该方法的有效性和优越性。

✅ 正确：实验结果表明，该方法在测试集上的准确率为95.6%，比基准方法高出8.2个百分点，运行时间为12.3秒。
```

### 七、自查清单

完成论文后，使用以下清单检查：

- [ ] 是否使用了"此外、另外、关键、深入探讨、充分展示"等AI高频词？
- [ ] 是否过度使用破折号、粗体、表情符号？
- [ ] 是否有"不仅...而且..."的否定平行结构？
- [ ] 是否强行将内容分成三组？
- [ ] 是否有模糊的归因（"专家认为"）？
- [ ] 是否有公式化的"挑战与展望"章节？
- [ ] 是否有通用的积极结论？
- [ ] 每句话是否都有具体数据或信息支撑？
- [ ] 是否变化了句子长度和结构？
- [ ] 是否承认了结果的复杂性和局限性？

**AI味量化阈值（必须遵守）：**
- 去AI味检测器（scorer.py 的 `ai_flavor_penalty` 维度）会在论文中搜索 40+ 个 AI 标记
- **通过门槛**：每篇论文 AI 标记 < 5 处 → `ai_flavor_penalty` 得分应 > 0.75
- 如果 scorer 报告中 `ai_flavor_penalty` < 0.65 → 必须逐条修正标记后再重新评分
- **重点排查**：此外、关键、充分展示、不仅而且、奠定基础、标志着、专家的认为
